# Fluxo de trabalho no GitHub

## 1. Escolha uma issue
Leia o objetivo e os critérios de conclusão antes de começar.

## 2. Crie uma branch
Use um nome curto que indique a tarefa, por exemplo `docs/glossario`. Trabalhe nela sem alterar a `main`.

## 3. Faça commits claros
Registre mudanças pequenas com mensagens que expliquem o que foi feito, como `docs: documenta o fluxo de PR`.

## 4. Abra um pull request
Compare a branch com `main`, descreva o que mudou e inclua `Closes #N` para relacionar a issue.

## 5. Peça revisão
Outra pessoa analisa o diff e pode aprovar, comentar ou solicitar mudanças específicas. Não aprove seu próprio PR.

## 6. Responda à revisão
Faça os ajustes na mesma branch e crie novos commits com mensagens claras. Responda a cada comentário explicando o ajuste.

## 7. Integre a mudança
Depois da aprovação e das verificações necessárias, faça o merge. Confirme que a issue foi fechada e remova a branch concluída.
